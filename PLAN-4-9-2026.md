## I. ATURAN BISNIS UTAMA (BUSINESS RULES)

### 1. Window Waktu Kegiatan & Jam Absensi
* **Waktu Buka Absen:** $\text{Jam Mulai} - 30\text{ menit}$.
* **Waktu Tutup Absen:** Tepat pada $\text{Jam Selesai}$ ($\text{Waktu Pulang}$).
* **Perhitungan Acara Lintas Hari / Malam Suntuk:**
  - Jika `tanggalSelesai` diisi $\rightarrow$ rentang dihitung dari `tanggal + jamMulai` s/d `tanggalSelesai + jamSelesai`.
  - Jika `tanggalSelesai` kosong tetapi `jamSelesai < jamMulai` (misal mulai `20:00`, selesai `05:00`) $\rightarrow$ sistem otomatis menganggap `jamSelesai` berada pada `tanggal + 1 hari`.
  - Contoh: Acara Sabtu 20:00 – 05:00.
    - Absen dibuka: Sabtu pukul `19:30`.
    - Absen ditutup: Minggu pukul `05:00`.
    - Scan pukul `01:00` Minggu dini hari $\rightarrow$ **VALID & AKTIF**.

### 2. QR Wilayah & Prinsip Pemindaian
* Setiap generus **SELALU dan HANYA** men-scan QR wilayah asalnya (`kelompokId` / `desaId` milik generus).
* Pada acara kolaborasi (misal Desa A mengundang Desa B), anak Desa B tetap scan **QR Desa B**.

### 3. Matriks Kelayakan Generus (Eligibility)
Kegiatan yang sedang aktif dinyatakan **Eligible** bagi Generus $G$ jika memenuhi:
1. **Lingkup Penyelenggara / Undangan:**
   - Acara Kelompok: `kegiatan.kelompokId === G.kelompokId`
   - Acara Desa: `kegiatan.desaId === G.desaId && kegiatan.kelompokId === null`
   - Acara Daerah: `kegiatan.desaId === null && kegiatan.kelompokId === null`
   - **ATAU Undangan Kolaborasi:** Wilayah/individu $G$ terdaftar di `kegiatan_peserta` status `approved`.
2. **Kriteria Target Peserta (jika kegiatan memiliki filter wajib):**
   - `kategoriMudaMudi`: cocok jika filter disetel (`pribumi` / `perantauan`).
   - `jenisKelamin`: cocok jika filter disetel (`L` / `P`).
   - `pendidikan`: cocok jika filter disetel (`SD`, `SMP`, `SMA`, `Kuliah`, `Sarjana`).
   - `usia`: dihitung dari `G.tanggalLahir` $\rightarrow$ harus berada dalam rentang `usiaMin` s/d `usiaMax`.
3. **Validasi Lokasi GPS:**
   - Jika `kegiatan.gpsRequired === 1`, jarak `haversineM(userLat, userLng, kegiatan.lat, kegiatan.lng) <= kegiatan.radiusM`.

### 4. Logika Keputusan & Resolusi Konflik Acara

Misalkan pada saat user $G$ scan QR:
* Himpunan $A = \{ \text{Semua kegiatan aktif yang } G \text{ eligible di waktu tersebut (Kelompok, Desa, Daerah, Kolaborasi)} \}$
* Himpunan $B = \{ \text{Semua kegiatan di } A \text{ yang spesifik terkait dengan QR Wilayah yang sedang discan} \}$

**Aturan Eksekusi:**
* **Kasus 1 ($B = 0$):**
  - Tidak ada acara aktif pada QR wilayah tersebut.
  - Tampilkan pesan: *"Tidak ada kegiatan aktif untuk wilayah ini saat ini."*
* **Kasus 2 ($B = 1$) — Single Match (Termasuk Bentrok Lintas Wilayah):**
  - **TIDAK MUNCUL MODAL**.
  - Catat $B[0]$ sebagai **`hadir`**.
  - Semua kegiatan lain di $A \setminus B$ (misal acara desa/daerah di jam yang sama) otomatis dicatat **`izin`** dengan catatan:
    `"Menghadiri kegiatan [Judul B[0]]"`.
* **Kasus 3 ($B \ge 2$) — Bentrok dalam 1 QR:**
  - **MUNCULKAN MODAL PILIHAN ACARA** berisi daftar kegiatan di $B$.
  - User memilih 1 kegiatan ($K_{\text{pilih}}$).
  - Catat $K_{\text{pilih}}$ sebagai **`hadir`**.
  - Semua kegiatan lain di $A \setminus \{K_{\text{pilih}}\}$ (baik sisa di $B$ maupun acara lintas wilayah) otomatis dicatat **`izin`** dengan catatan:
    `"Menghadiri kegiatan [Judul K_pilih]"`.

### 5. Snapshot Wilayah (Point-in-Time Integrity)
* Kolom `desaId` dan `kelompokId` pada tabel `absensi` menyimpan status wilayah generus saat transaksi absensi terjadi.
* Query agregasi statistik menggunakan `COALESCE(absensi.desa_id, generus.desa_id)` sehingga mutasi generus di masa depan tidak merusak histori statistik masa lalu.

### 1. Utility Evaluasi Waktu: `server/src/utils/kegiatanTime.ts`

```typescript
export type EventTimeWindow = {
  start: Date;
  end: Date;
  windowOpen: Date;   // start - 30 mins
  windowClose: Date;  // end (exact waktu pulang)
};

export function getEventTimeWindow(k: {
  tanggal: string;
  tanggalSelesai?: string | null;
  jamMulai?: string | null;
  jamSelesai?: string | null;
  jam?: string | null;
}): EventTimeWindow {
  const startTimeStr = k.jamMulai || k.jam || "00:00";
  const start = new Date(`${k.tanggal}T${startTimeStr.length === 5 ? startTimeStr + ":00" : startTimeStr}`);

  let end: Date;
  if (k.tanggalSelesai && k.jamSelesai) {
    const endTimeStr = k.jamSelesai.length === 5 ? k.jamSelesai + ":00" : k.jamSelesai;
    end = new Date(`${k.tanggalSelesai}T${endTimeStr}`);
  } else if (k.jamSelesai) {
    const endTimeStr = k.jamSelesai.length === 5 ? k.jamSelesai + ":00" : k.jamSelesai;
    if (k.jamSelesai < startTimeStr) {
      const nextDay = new Date(start);
      nextDay.setDate(nextDay.getDate() + 1);
      const nextDateStr = nextDay.toISOString().slice(0, 10);
      end = new Date(`${nextDateStr}T${endTimeStr}`);
    } else {
      end = new Date(`${k.tanggal}T${endTimeStr}`);
    }
  } else {
    end = new Date(start.getTime() + 2 * 60 * 60 * 1000);
  }

  const windowOpen = new Date(start.getTime() - 30 * 60 * 1000); // -30 Menit
  const windowClose = end;                                       // Tepat Waktu Pulang

  return { start, end, windowOpen, windowClose };
}

export function isEventActiveNow(k: any, now: Date = new Date()): boolean {
  const { windowOpen, windowClose } = getEventTimeWindow(k);
  return now >= windowOpen && now <= windowClose;
}
```

### 2. Utility Evaluasi Kelayakan Generus: `server/src/utils/eligibility.ts`

```typescript
import { haversineM } from "../../../shared/validation";

export function calculateAge(birthDateStr?: string | null, referenceDate: Date = new Date()): number | null {
  if (!birthDateStr) return null;
  const b = new Date(birthDateStr);
  if (Number.isNaN(b.getTime())) return null;
  let age = referenceDate.getFullYear() - b.getFullYear();
  const m = referenceDate.getMonth() - b.getMonth();
  if (m < 0 || (m === 0 && referenceDate.getDate() < b.getDate())) {
    age--;
  }
  return age;
}

export function isGenerusEligibleForKegiatan(
  generus: {
    id: string;
    desaId: number | null;
    kelompokId: number | null;
    jenisKelamin: string;
    kategoriMudaMudi?: string | null;
    pendidikan?: string | null;
    tanggalLahir?: string | null;
  },
  kegiatan: any,
  pesertaEntries: any[],
  userLocation?: { lat: number; lng: number } | null
): boolean {
  if (kegiatan.gpsRequired === 1 && kegiatan.lat != null && kegiatan.lng != null) {
    if (!userLocation) return false;
    const dist = haversineM(userLocation.lat, userLocation.lng, kegiatan.lat, kegiatan.lng);
    if (dist > (kegiatan.radiusM || 100)) return false;
  }

  let isInvitedOrInScope = false;
  const directApproved = pesertaEntries.some(
    (p) => p.kegiatanId === kegiatan.id && p.status === "approved" && (
      (p.generusId && p.generusId === generus.id) ||
      (p.kelompokId && p.kelompokId === generus.kelompokId) ||
      (p.desaId && p.desaId === generus.desaId)
    )
  );

  if (directApproved) {
    isInvitedOrInScope = true;
  } else if (!kegiatan.desaId && !kegiatan.kelompokId) {
    isInvitedOrInScope = true;
  } else if (kegiatan.desaId && !kegiatan.kelompokId && kegiatan.desaId === generus.desaId) {
    isInvitedOrInScope = true;
  } else if (kegiatan.kelompokId && kegiatan.kelompokId === generus.kelompokId) {
    isInvitedOrInScope = true;
  }

  if (!isInvitedOrInScope) return false;

  if (kegiatan.targetJenisKelamin && kegiatan.targetJenisKelamin !== generus.jenisKelamin) return false;
  if (kegiatan.targetKategoriMudaMudi && kegiatan.targetKategoriMudaMudi !== generus.kategoriMudaMudi) return false;
  if (kegiatan.targetPendidikan && kegiatan.targetPendidikan !== generus.pendidikan) return false;

  const age = calculateAge(generus.tanggalLahir);
  if (kegiatan.targetUsiaMin != null && (age == null || age < kegiatan.targetUsiaMin)) return false;
  if (kegiatan.targetUsiaMax != null && (age == null || age > kegiatan.targetUsiaMax)) return false;

  return true;
}
```

## IV. BACKEND ENDPOINTS (`server/src/routes/absensi.ts`)

1. **`POST /api/absensi/scan`**
   - Payload: `{ qrToken, lat, lng, accuracy }`
   - Logika:
     - Dapatkan identitas user `generus`.
     - Filter kegiatan aktif $A$ (semua kegiatan aktif yang user eligible).
     - Filter kegiatan $B \subseteq A$ (kegiatan yang terikat spesifik dengan QR wilayah yang discan).
     - Jika $B = 0 \rightarrow$ return `{ status: "no_event", message: "Tidak ada kegiatan aktif untuk wilayah ini." }`.
     - Jika $B = 1 \rightarrow$ simpan `hadir` untuk $B[0]$ + simpan `izin` untuk $A \setminus B$ dengan snapshot wilayah (`desaId`, `kelompokId`) dan `catatan: "Menghadiri kegiatan " + B[0].judul`. Return `{ status: "success", attendedKegiatan: B[0] }`.
     - Jika $B \ge 2 \rightarrow$ return `{ status: "multiple", eligibleKegiatan: B, allConcurrentKegiatan: A }`.

2. **`POST /api/absensi/resolve`**
   - Payload: `{ selectedKegiatanId, allEligibleKegiatanIds, lat, lng, accuracy, qrWilayahLevel }`
   - Logika:
     - Simpan `hadir` pada `selectedKegiatanId` (dengan snapshot `desaId` & `kelompokId`).
     - Simpan `izin` pada semua kegiatan di $\text{allEligibleKegiatanIds} \setminus \{\text{selectedKegiatanId}\}$ dengan snapshot dan `catatan: "Menghadiri kegiatan " + selectedKegiatan.judul`.

3. **`GET /api/statistik` (`server/src/routes/statistik.ts`)**
   - Query absensi per wilayah menggunakan `COALESCE(absensi.desa_id, generus.desa_id)` dan `COALESCE(absensi.kelompok_id, generus.kelompok_id)` agar histori tidak bergeser saat generus mutasi.
